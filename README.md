# Поток: визуальный конструктор ветвящихся квизов

Поток: визуальный конструктор ветвящихся квизов — это мощное и интуитивно понятное веб-приложение для создания и предварительного просмотра персонализированных разветвлённых викторин с помощью визуального редактора. Приложение создано на React и ReactFlow, имеет современный дизайн, поддерживает различные типы узлов для сложной логики и генератор HTML-викторин. Приложение интегрировано с Supabase для аутентификации пользователей, что позволяет хранить викторины в облаке.

## ✨ Основные функции

- **Редактор визуального потока:** перетаскивайте и соединяйте узлы на бесконечном холсте, чтобы создать логику викторины.
- **Богатая библиотека узлов:** полный набор узлов, включая вопросы, варианты ответов, условную логику, подсчет баллов, сбор данных и многое другое.
- **Настройка дизайна в реальном времени:** специальная панель для настройки шрифтов, цветов, фона и стилей кнопок с предварительным просмотром в реальном времени.
- **Мгновенный предварительный просмотр:** мгновенно протестируйте логику и дизайн викторины в большом модальном окне предварительного просмотра, которое точно отражает конечный результат.
- **Импорт/экспорт JSON:** сохраните структуру викторины локально или поделитесь ею с другими, экспортировав в файл JSON.
- **Создание HTML-кода в один клик:** создайте отдельный HTML-файл для своей викторины, который можно будет развернуть где угодно.
- **Интеграция с Supabase:** аутентификация пользователей (регистрация/вход в систему) уже реализована, что позволяет использовать в будущем функции облачного хранения.
- **Адаптивный и профессиональный пользовательский интерфейс:** и редактор, и созданные викторины имеют чистый, современный и адаптивный дизайн.

## 🏗️ Архитектура (кратко)

- **In-app preview** (`LivePreview`, `Header.handlePreview`, `QuizCard`, `QuizPlayer`) рендерит квиз в `<iframe sandbox="allow-scripts allow-same-origin" srcdoc>`. Движок подгружается как `<script type="module" src="/__quiz_engine.js">` — этот URL отдаёт Vite-middleware в dev и `vite build` эмитит его в `dist` для production-хостинга. Данные передаются через `<script id="quiz-data" type="application/json">`. Такой путь совместим со строгим `script-src 'self'` родительской страницы.
- **Standalone export** (скачиваемый HTML) — self-contained файл с inline-движком и собственным CSP (`'unsafe-inline'`, CDN allowlist). Открывается offline без сервера.
- **Один источник логики:** [`src/engine`](./src/engine). Rollup собирает его в `.generated/quizEngine.iife.js`; preview компилирует тот же entry через `vite-plugin-quiz-engine.ts`, а standalone импортирует IIFE как текст через [`services/quizEngine.ts`](./services/quizEngine.ts). Подробности: [`QUIZ_ENGINE_ARCHITECTURE.md`](./QUIZ_ENGINE_ARCHITECTURE.md).
- **DOMPurify** вшивается в движок через Vite-овский `?raw` import — `services/dompurify-bundle.ts` + plugin в `vite-plugin-quiz-engine.ts:60-90`, чтобы esbuild понимал `?raw`-суффикс (нативно поддерживает только `loader: "text"`).

> ⚠️ CSP в `index.html` разрешает `'unsafe-eval'` — это намеренный trade-off для движка и template runner в in-app preview. Chromium intersect'ит CSP родителя и iframe-meta, отдельное ослабление для iframe невозможно.

## 🚀 Начало работы

Этот проект представляет собой статическое веб-приложение, которое можно запустить, открыв файл `index.html` в современном веб-браузере. Однако для полноценной работы (например, для аутентификации пользователей) вам потребуется настроить Supabase.

### Настройка

Чтобы аутентификация пользователей и будущие облачные функции работали, вам нужно подключить приложение к вашему собственному проекту Supabase.

1. **Создайте базовый проект:** Если у вас его еще нет, перейдите по ссылке [supabase.com](https://supabase.com/) и создайте новый проект.
2. **Получите учетные данные API:** На панели управления проектом Supabase перейдите в "Настройки проекта" > "API". Вы найдете URL-адрес своего проекта и свой открытый ключ `anon`.
3. **Обновите клиент:** Откройте файл `services/supabaseClient.ts` в проекте. Замените значения-заполнители на свой фактический URL-адрес Supabase и анонимный ключ: 

    ```typescript
    // services/supabaseClient.ts

    // ВАЖНО: замените на свой фактический URL-адрес Supabase и анонимный ключ
    const supabaseUrl = 'YOUR_SUPABASE_URL'; // Замените на URL-адрес вашего проекта Supabase
    const supabaseAnonKey = 'YOUR_SUPABASE_ANON_KEY'; // Замените на анонимный ключ вашего проекта Supabase
    ```

4.  **Включите аутентификацию по электронной почте.** На панели управления Supabase перейдите в раздел `Аутентификация` > `Провайдеры` и убедитесь, что провайдер `Электронная почта` включен.

## 🚀 Развертывание в Яндекс Облаке

Приложение разворачивается как статический SPA в **Yandex Object Storage** (S3-совместимый) с раздачей через **Yandex CDN**. Авторизация и БД остаются в Supabase, AI-прокси — Supabase Edge Function `ai-proxy`.

Полная инструкция: [`deploy/README.md`](./deploy/README.md).

### Быстрый старт

1. **Установите CLI:**
   - [AWS CLI](https://aws.amazon.com/cli/) (для S3-совместимого API).
   - [Yandex Cloud CLI `yc`](https://yandex.cloud/ru/docs/cli/quickstart) (опционально, для CDN purge).
2. **Подготовьте Яндекс Облако:**
   - Создайте сервисный аккаунт с ролью `storage.editor`.
   - Создайте бакет в Object Storage (public-read).
   - (Опционально) Подключите CDN-ресурс с origin = `<bucket>.website.yandexcloud.net`.
3. **Заполните `.env`** на основе `.env.example` — добавьте `VITE_SUPABASE_*`, `YC_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`.
4. **Запустите деплой:**
   ```powershell
   # Windows (PowerShell)
   ./deploy/deploy.ps1
   ```
   ```bash
   # Linux / macOS
   ./deploy/deploy.sh
   ```

### CI/CD

В репозитории есть готовый workflow `.github/workflows/deploy.yml` — он автоматически собирает и публикует проект в Yandex Object Storage при push в `main`. Список секретов GitHub Actions смотрите в [`deploy/README.md`](./deploy/README.md#4-cicd-через-github-actions).

### Настройка Supabase

После первого деплоя:
- В **Supabase → Authentication → URL Configuration** добавьте URL бакета/CDN в `Site URL` и `Redirect URLs`.
- В переменных окружения Edge Function `ai-proxy` обновите `AI_PROXY_ALLOWED_ORIGINS`, чтобы разрешить CORS для нового домена.
