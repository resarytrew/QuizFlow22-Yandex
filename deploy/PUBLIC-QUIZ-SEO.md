# Публичные квизы в поиске

`/quizzes/index.html` — серверный каталог с пагинацией по 24 проекта.
`/quizzes/<UUID>.html` — название, описание, темы и ссылка на прохождение.
`/quizzes/sitemap.xml` — динамический sitemap index; дочерние файлы содержат
каталог и все доступные проекты (по 1000 URL), без лимита галереи в 200 записей.

Все запросы читают PostgreSQL с единым фильтром: visibility=public,
deleted_at IS NULL, moderation_status=approved (отсутствие значения в старой
схеме считается approved). Private, unlisted, pending, blocked, hidden,
rejected и удалённые проекты не возвращаются. После смены статуса страница
отдаёт 404 + noindex, а URL исчезает из sitemap. Удаление уже сохранённой
копии из поискового индекса происходит после повторного обхода роботом.

Ответы имеют Cache-Control: no-store; правило CDN отключает кэширование.
Ошибка БД возвращает 503 + Retry-After, а не пустой sitemap с кодом 200.
В HTML попадают только экранированные названия, описания и ключевые слова.
Нет ответов на вопросы, результатов пользователей, данных аккаунта или паспорта.
Для отсутствующего описания используется честная общая подпись с названием.
Авторам рекомендуется заполнить описание и темы в настройках проекта.

## Развёртывание

Это отдельная read-only Cloud Function и отдельный API Gateway. Основной API
и его маршруты не меняются. Gateway явно использует payload_format_version=1.0.
Новая функция получает существующие PG_* привязки Lockbox без чтения значений.

```powershell
npm --prefix yc-functions run build:seo
./deploy/deploy-public-quiz-seo.ps1 -Yc "$env:USERPROFILE/yandex-cloud/bin/yc.exe"
./deploy/configure-public-quiz-cdn.ps1 -Yc "$env:USERPROFILE/yandex-cloud/bin/yc.exe"
```

CDN-правило public-quiz-seo с весом 5 и шаблоном `^/quizzes(?:/.*)?$`
направляет только этот префикс на gateway, задаёт его Host и отключает rewrite
и кэш. Существующий SPA fallback сохраняется для остальных адресов.
После распространения настройки проверить публичный домен:

```shell
npm run check:public-seo
```

Frontend деплоится существующим workflow из актуальной production-ветки.
Изменения функции требуют отдельного запуска скрипта выше; frontend workflow
не меняет серверную функцию. В обычный build функций включена её компиляция.

## Поисковики

robots.txt ссылается на оба sitemap. Главная и названия карточек галереи
ведут на новые страницы обычными HTML-ссылками. В Яндекс Вебмастере добавить
https://mykviz.ru/quizzes/sitemap.xml и отправить каталог/текущие квизы на переобход.
Новые публикации далее обнаруживаются через динамические sitemap и каталог.
Наличие в sitemap не гарантирует включение или позиции в поиске.

Проверки: unit-тесты HTML escaping, фильтра допуска, снятия публикации,
пагинации, XML, ошибок БД, маршрутов gateway и GET/HEAD; live-проверка
HTTP, MIME, canonical, HTML без JS и no-store через CDN.
