# Проверка и восстановление оплаты

Тариф активируется после проверки платежа через API ЮKassa. Основной путь —
`POST https://api.mykviz.ru/api/billing/yookassa-webhook?key=<BILLING_WEBHOOK_SECRET>`.
В кабинете ЮKassa в разделе «Интеграция → HTTP-уведомления» должны быть включены
`payment.succeeded` и `payment.canceled` с этим URL. Значение `key` берётся из
Lockbox; его нельзя публиковать в логах, задачах или pull request.

Резервный путь — авторизованный `get-entitlement`: сайт проверяет до трёх
неприменённых платежей аккаунта, не чаще одного запроса на платёж за 15 секунд.
Он проверяет ID, сумму, валюту и привязку к аккаунту/тарифу. `pending`,
`waiting_for_capture`, отменённые и возвращённые платежи не дают доступ.
Сбой ЮKassa не мешает прочитать уже действующий доступ; проверка будет повторена.
При возврате с оплаты `/billing/return` ждёт подтверждение до минуты.

Все пути используют одну транзакцию и журнал `payment_applications`:
повторный webhook, проверка из браузера и восстановление администратором
не добавляют второй оплаченный период. Уже учтённые исторические платежи
с отметкой `legacy` не восстанавливаются автоматически.

## Зависшие платежи

Сначала выполните проверку без изменений в базе:

```powershell
npm --prefix yc-functions run build:billing-recovery
$env:YC_CLI = 'C:/Users/enekr/yandex-cloud/bin/yc.exe'
node yc-functions/dist/billing-recovery/index.cjs --from-yandex
```

Скрипт читает актуальные привязки секретов API-функции в память и сверяет
неприменённые платежи с ЮKassa. В выводе нет ключей и email пользователей.
Для production нужен доступ `yc` к функции и Lockbox и сетевой доступ к PostgreSQL.
Альтернатива — задать `PG_*` и `YOOKASSA_*` в окружении и убрать `--from-yandex`.

После проверки отчёта восстановление выполняется явно:

```powershell
node yc-functions/dist/billing-recovery/index.cjs --from-yandex --apply
```

Скрипт предоставляет оплаченный период с момента восстановления (либо
продлевает действующую подписку), не создаёт новых списаний и не делает возвратов.
Повторный запуск безопасен: применённые платежи пропускаются.
Для одного платежа можно использовать «Проверить платёж» / «Восстановить доступ»
в рабочем пространстве пользователя в админке.

Если аккаунту уже выдали PRO вручную или по промокоду, сначала сверьте причину
этой выдачи: она могла компенсировать зависший платёж. Автоматический скрипт
сохраняет такой доступ и создаёт отдельную платную подписку; его `--apply`
следует запускать после проверки, что платный период ещё не был предоставлен.

Документация: [уведомления ЮKassa](https://yookassa.ru/developers/using-api/webhooks),
[формат события API Gateway](https://yandex.cloud/ru/docs/api-gateway/concepts/extensions/cloud-functions).
